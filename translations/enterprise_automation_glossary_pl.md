# Enterprise Automation — glosariusz EN → PL

Ten glosariusz definiuje preferowaną terminologię dla polskiej wersji systemu projektowego i jego dokumentacji.

Format:
TERMIN
Preferowane tłumaczenie: ...
Uwagi: ...

## Środowisko techniczne i dane

payload
Preferowane tłumaczenie: dane wejściowe
Uwagi: Nie tłumacz jako "ładunek" ani "odpowiedź". W kontekście HTTP "payload" oznacza treść przesyłaną w żądaniu lub odpowiedzi — "dane wejściowe" / "treść żądania".

response payload
Preferowane tłumaczenie: treść odpowiedzi
Uwagi: Rozróżnij od "payload" w żądaniu.

stack trace
Preferowane tłumaczenie: ślad stosu
Uwagi: NIGDY nie tłumacz jako "stos wyjątków". "Stos" w polskim oznacza właśnie stos wyjątków, więc dosłowna kalka tworzy zdanie "pełne stosy wyjątków", które nie znaczy śladu wywołań.

Preferowane tłumaczenie: żądanie / odpowiedź

error log
Preferowane tłumaczenie: dziennik błędów

log
Preferowane tłumaczenie: log / dziennik
Uwagi: W kontekście technicznym "log" jest przyjęte.

stdout / stderr
Preferowane tłumaczenie: standardowe wyjście / standardowe wyjście błędów
Alternatywnie: pozostaw stdout / stderr przy cytowaniu poleceń.

## Typografia — terminologia

line
Preferowane tłumaczenie: linia
Uwagi: "Linia" to pojedynczy wiersz tekstu. "Wiersz" w polskiej typografii oznacza wiersz tabeli albo akapit — nie linię.

unified
Preferowane tłumaczenie: spójny
Uwagi: Nie tłumacz jako "jednolity" (oznacza jednorodność, wszystko identyczne). Dla systemu projektowego właściwe jest "spójny".

coherent
Preferowane tłumaczenie: spójny

consistent
Preferowane tłumaczenie: spójny / konsekwentny
Uwagi: "Konsekwentny" oznacza stosowany bez wyjątków; "spójny" — wzajemnie zgodny.

row
Preferowane tłumaczenie: wiersz
Uwagi: Wiersz tabeli lub listy. Nie myl z "linia".

column
Preferowane tłumaczenie: kolumna

heading
Preferowane tłumaczenie: nagłówek
Uwagi: Nagłówek dokumentu lub sekcji. "Nagłówek tabeli" to "table header", nie "nagłówek kolumny".

overline
Preferowane tłumaczenie: nadtytuł
Uwagi: Mały wersalnik nad tytułem sekcji.

## Zasady ortograficzne

### Liczba i jednostka

W prozie liczbę i jednostkę rozdziela **spacja**:

- `13,5–15 px` — tak
- `13,5–15px` — nie
- `320 px`, `300 ms`, `4 px`, `5,22:1`

Separator dziesiętny to **przecinek**, nie kropka: `4,5:1`, `13,5 px`.

W identyfikatorach i nazwach technicznych spacji nie ma — to nie jest proza:

- `--bg-surface-2` — bez spacji
- `24×24px` — bez spacji
- `400ms` w kontekście technicznym — bez spacji
- `sm`, `md`, `lg`, `ds-1` — bez spacji

Nie stosuj twardej spacji (`U+00A0`) w plikach źródłowych — zwykła spacja wystarcza i nie komplikuje diffów.

### Znaki przestankowe

- Cudzysłowy polskie: `„…"`, nie `"…"`
- Myślnik w treści: `–` (U+2013), w zakresach liczbowych: `–`
- Pionowa kreska przedrostkowa w złożeniach: `–`, np. `zoptymalizowane pod kątem`
- Wielokropek: `…` (U+2026), nie trzy kropki

### Interpunkcja po polsku

- Przecinek przed spójnikiem `i`, `lub`, `albo`: `tokeny, komponenty i wzorce`
- Średnik lub kropka przed zdaniem wyliczenia, nigdy wielka litera po środku zdania
